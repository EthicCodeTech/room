# Room 1.2: plan

Status: proposal. Room 1.2 is the first release for everyone, on **Mac and Windows** ([windows-plan.md](windows-plan.md)).

## 1. Themes

1. **Room knows how you work.** A first-run screen asks what you do most on this computer, and Room tailors what it looks for.
2. **Windows.** Same product, native to the platform.
3. **No scary first run.** For "everyone" the Mac Open Anyway step has to go (notarization, section 6).
4. **Safer around real projects.** Rules know when an app is running or a project is in use.

## 2. First-run flow (Mac and Windows)

Room has no onboarding today, so this is new.

1. **Welcome**: one sentence on what Room does and the privacy promise (no accounts, nothing leaves this computer).
2. **"What do you do most on this Mac?"** (or "on this PC"): a grid of cards, **multi-select**, pick as many as you like. A **"Just everyday use"** card is always available and **Skip** is allowed.
3. **Where is your stuff?** (only when relevant): lists external drives and other drives it can see, and lets the user add folders for projects, media or libraries.
4. **Permissions, explained first**: on Mac, why Room asks for Desktop / Documents / Downloads access; on Windows, nothing to grant.
5. **First scan**, then straight to the Overview with a line such as "Because you edit video, Room also checked your media caches."

Everything chosen here is editable later in Settings. Nothing about the choice is uploaded, and it is not part of the anonymized decision record.

### What the choice changes (and what it must not)

- **Changes:** which persona rules are switched on, which folders are scanned, how suggestions are ranked (a small prior boost for what matters to that work), and the wording on cards.
- **Must not change:** safety. A persona can never move an item to a lower-risk tier, never preselect a `yours` item, and never relax the git guard. Persona only decides *what to look for*, not *how careful to be*.

### The SVGs

- **Source:** [Lucide](https://lucide.dev) (ISC license) gives one consistent line-icon family, which suits Cinnabar's hairline look. Names above are proposals to confirm against the current icon set; where no icon fits (for example "game development"), draw a custom one in the same grid.
- **Spec:** 24x24 grid, 1.5 px stroke, round caps and joins, `currentColor` so the icons follow light and dark and the cinnabar accent when selected.
- **Delivery:** one build step turns shapes into plain path data (the Mac app already ships an SVG path parser, `SVGPath.swift`) and writes a sprite for the Windows UI. Third-party license text goes in `Brand/ICONS-LICENSE.txt`.
- **Alternative:** commission a custom set from the designer who made the Room logo, for a distinctive look. Slower and costs money, so this is optional for 1.2.

## 4. Persona-driven rules

Rules gain a `personas` field (the catalog already has `tags`). Each rule below is a *candidate* and **must be verified on a real install before it ships**: paths and cache behaviour change between app versions.

| Persona | Candidate rules | Tier / guard |
| --- | --- | --- |
| Developing | Existing set, plus Docker / VM images, language caches | as today |
| Mobile apps | Xcode DerivedData, old iOS DeviceSupport, Simulator runtimes (Mac); Android AVD / Gradle (both) | rebuildable |
| Game development | Unity `Library/` and `Temp/`, Unreal `DerivedDataCache`, `Intermediate`, `Saved` in stale projects | rebuildable, hours to rebuild, warn |
| Data science & AI | `pip` / `conda` / `uv` caches, Hugging Face cache, Ollama models | caches rebuildable, **models `yours`** (large downloads) |
| Video editing | Premiere media cache, After Effects disk cache, DaVinci CacheClip, Final Cut render files | rebuildable. **Guard:** app not running and project not opened recently, so no 45-minute re-index surprises |
| Music & audio | Ableton crash/backup files, Logic bounces and freeze files, duplicate installers and sample-pack zips | zips and installers vaulted; **never move plugins or samples** that projects reference by path |
| Photography | Lightroom previews and Camera Raw cache, Capture One cache | rebuildable; the **catalog and originals are never suggested** |
| Design | Figma / Adobe caches and scratch files, Sketch autosave | rebuildable |
| 3D & animation | Blender temp, render caches, Maya autosave | rebuildable; outputs are `yours` |
| Gaming | Shader caches; launchers' download caches; **never game installs** (shown in the Map only) | rebuildable |
| Trading & finance | Charting-app (Electron) caches only. Tick data and history are `yours`, **shown in the Map, never suggested** | cache only |
| Streaming & content | Old recordings and exports (largest-first list for the user to pick) | `yours` |
| Everyday | Chat-app media caches (WhatsApp, Telegram, Discord), browser caches, system update leftovers | chat media is `yours` (personal photos), shown grouped by size before anything is removed |

### Shared safety upgrades (both platforms)

- **"App is running" guard.** A rule can name apps; if one is open, the rule is held back with "Close Premiere to include this."
- **Cloud-synced folder guard** (iCloud Drive, OneDrive, Dropbox): treat as `yours`, and warn "this also deletes it from the cloud". Needs a check of how the Mac app handles iCloud-synced Desktop and Documents today before 1.2.
- **Project awareness** for creative tools: skip projects modified recently.

## 5. Other 1.2 work

- **Catalog as signed JSON** (shared with Windows), with signature checking switched on.
- **Auto-update** (Sparkle on Mac, the Tauri updater on Windows), opt-in.
- **Accessibility pass** on the picker: full keyboard use, VoiceOver and Narrator labels, selected state not relying on colour alone.
- **Localization groundwork**: strings out of views. Languages are a later release.

## 6. Ship blockers for "everyone"

1. **Apple notarization** (needs an Apple Developer ID). Without it, every Mac user still has to do the Open Anyway steps, which is fine for early adopters and a poor fit for a general audience.
2. **Windows signing route** decided (see [windows-plan.md](windows-plan.md), section 8).
3. **Real-world test on an Intel Mac and on Windows**, since neither has been tested on real hardware yet.

## 7. Milestones

| Phase | Outcome |
| --- | --- |
| **A. Design** (1 to 2 wks) | OOBE screens (light and dark), card copy, icon set chosen, persona rule list reviewed |
| **B. Mac** (3 to 4 wks) | Settings field, OOBE, catalog v2 loader, persona rules, app-running guard, notarization |
| **C. Windows** | Follows the windows-plan.md milestones; OOBE reuses the same card data |
| **D. Beta** | Mac and Windows beta together |
| **E. Launch** | 1.2 on both |

A shared `personas.json` (id, title, description, icon, platforms) feeds both OOBE screens so the two apps cannot disagree.
